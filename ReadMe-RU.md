# Loadout ModSync

[日本語版](ReadMe-JP.md)

Loadout ModSync — лаунчер для Windows и дополнение к **Project Zomboid ДЕДИКАТЕД Server**. Сервер качает моды из Steam Workshop через SteamCMD. Абоненты получают файлы, с которыми **сейчас запущен сервер**, а не то, что Воркшоп выкатил пять минут назад.

Разраб выкатил обнову, а сервер ещё не ребутался? Ничего страшного, лаунчер подтянет серверную версию. Без вечного круга «перезайди, отпишись, подпишись, теперь ещё раз перезайди». **Первый раз сборку всё равно надо скачать.** Потом качается только то, чего не хватает или что поменялось. Один файл изменился в одном моде? Докачается один файл, а не весь модпак.

Гайд, справочник, инструкция, не важно, для **0.1.3**. Клиент проверяли на Windows, сервер на **Build 42.22.2**. На других билдах и Docker-образах чудес не обещаю, но поидее до 43 билда по крайней мере все должно работать. Хотя хрен знает может они имена процессов поменяют и все накроется медным тазом.

## АБОНЕНТАМ (игрокам)

Нужны Project Zomboid в Steam, версия игры как у сервера, Windows x64 и **адрес ModSync от админа**. Адрес для скачивания модов и адрес с портом для входа в игру — две разные вещи. Не пихай один в оба поля.

1. Возьми ZIP для Windows x64 у админа или в **Releases**. Исходники для игры не нужны.
2. Распакуй **весь ZIP**, например в `C:\Games\LoadoutModSync`. Запусти `DNTSNE-ModSync.exe`. Да, имя EXE пока старое. Папка `_internal` должна лежать рядом. EXE без неё хоть уговаривай, хоть нет, не запустится. Отдельно ставить Python не надо.
3. Запусти Steam. Если сервер сидит за Tailscale, Radmin VPN или другой такой штукой, подключись к сети, которую дал админ. Если доступ и так есть, ничего дополнительно ставить не надо. **Перед синком закрой Project Zomboid.**
4. Открой **Settings**. В **Tailscale server URL** впиши адрес от админа. `http://pz-host:8787` — просто пример. В **Game folder** укажи папку игры, если лаунчер сам её не нашёл. В Steam: **Свойства → Установленные файлы → Обзор**. Дальше копируй путь из Проводника, я в тебя верю. Если админ дал уже настроенный лаунчер, просто проверь адрес и папку игры.
5. **Mod folder** лучше не трогать. По умолчанию это `%LOCALAPPDATA%\DNTSNE\ModSync\game-profile\mods`. **Не указывай папку Steam Workshop**, дурень. Нажми **Save**.
6. Нажми **Synchronize** и жди готовности или конкретной ошибки, а не гадай по полоске. На первый синк нужен запас места **больше размера модпака**: временные файлы тоже где-то живут.
7. Нажми **Launch Project Zomboid**. Для этой сборки запускай игру **из лаунчера, не кнопкой Steam**. В самой игре введи адрес и порт от админа.

Лаунчер не трогает подписки Workshop и не обновляет саму игру. Нужна ванилла или обычные моды Workshop? Запускай PZ из Steam как раньше. И не запускай синк в двух лаунчерах сразу: папка общая, они там за файлы подерутся.

### ЕСЛИ НЕ РАБОТАЕТ

- **Версия игры не та.** Сверь точный билд и ветку с админом. Игру обновляют через Steam, не через ModSync.
- **Сервер не отвечает или обновляется.** Проверь URL и сеть. Если у товарищей тоже не работает, пусть админ посмотрит, готова ли раздача. Тут переустановка у тебя ничего не вылечит.
- **Синк прошёл, но игра матерится на моды.** Закрой игру и попробуй **Settings → Full verification (reads every file)**. Не сноси папку модов вслепую: там могут быть твои файлы. Если дошло до чистой установки, сначала сохрани то, что добавлял сам.
- **Вообще непонятно, где застряло.** Нажми **Open log file**, возьми пару строк с ошибкой и скинь админу. Хочешь спросить ChatGPT или Claude — пожалуйста, только вырежи токены, пароли и приватные адреса. «Не работает, почини» даже админа не просветлит.

## ЛАРПЕРАМ (админам)

| Где | Что там работает |
| --- | --- |
| **HOST** | Официальный пакет Dedicated Server внутри совместимого Docker-образа. SteamCMD и WorkshopManager остаются на месте. |
| **HOST** | ModSync API в отдельном Compose-проекте и `dntsne-monitor` в systemd. Первый раздаёт файлы, второй смотрит, что сейчас запущено. |
| **CLIENT** | Лаунчер. А чему там ещё работать? |

### Установка на сервер

Все равно на сервер будет все ставить иишка я в курсе. Поэтому вот:
**Если сервер уже работает в Linux с Docker Compose и systemd**, короткий порядок. Пример подходит для образа PZ с WorkshopManager и файлами `/scripts/config/main.py` и `/scripts/init-server.sh`. Для другого образа или Windows Dedicated Server готового установщика пока нет.

1. **Сделай копию мира, INI и Compose.** Для пробы возьми отдельный контейнер и копию мира, а не сервер, на котором сейчас играют.
2. **Установи раздачу модов.** В исходниках открой `deploy/compose.modsync.yaml`, замени адрес и пути на свои. Используй приватный адрес, например Tailscale или с клаудфларе я хз. Затем из папки проекта пропиши:

   ```bash
   sudo sh scripts/install-server.sh --approved
   ```

   Скрипт ставит наблюдатель и API. **ОН НЕ НАСТРАИВАЕТ САМ PZ СЕРВЕР и не перезапускает его.**
3. **Подключи моды к игровому серверу.** Возьми `deploy/compose.pz.override.example.yaml`, подставь свои пути и подключи его к тестовому Compose. В настройках запуска оставь `WORKSHOP_ITEMS` для SteamCMD. После запуска проверь, что в итоговом INI строка `WorkshopItems=` пустая, а `Mods=` и `Map=` остались с нужными значениями. [Пример с путями и подготовкой файла запуска](docs/SERVER-SETUP.md).
4. **Включи раздачу и проверь.** После проверки условий распространения модов включи раздачу через `DNTSNE_LICENSES_APPROVED=1` по [инструкции](docs/SERVER-SETUP.md). С другого ПК в той же сети открой `http://ИМЯ-ХОСТА:8787/api/v1/status`. Если видишь `"state":"ready"`, дай игрокам адрес `http://ИМЯ-ХОСТА:8787`. Адрес для входа в игру сообщи отдельно на кой черт я все обьясняю ты же не тупой если читать пошел...

**Дальше при обновлении:** штатно перезапусти PZ, дождись `SERVER STARTED` и попроси игроков нажать **Synchronize**. НЕ ОБНОВЛЯТЬ папку Workshop вручную, пока сервер работает.

## Разработка и планы

Чтобы запустить клиент из исходников в PowerShell, из корня проекта:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-client.lock
.\.venv\Scripts\python.exe client_app.py
```

Нужен Python **3.12+**; используй версию, для которой устанавливаются зависимости из lock-файла. Для тестов поставь также зависимости из `requirements-server.lock` и `pytest`, затем запусти `.\.venv\Scripts\python.exe -m pytest`. Чтобы собрать Windows-пакет, используй `scripts/build-client.ps1`. Результат будет в `dist/0.1.3/DNTSNE-ModSync`. Упаковывай всю папку вместе с `_internal`, а не только EXE.
