# Протокол и целостность

В 0.1.2 успешная установка сохраняет небольшой ready.json с ревизией, версией PZ, количеством файлов и fingerprint committed registry. При прежней ревизии GUI не сканирует моды и не читает полный manifest. Повторный запуск восстанавливает эту запись. Старые завершённые установки мигрируют из registry и сохранённого manifest без чтения самих модов. Незавершённый journal, изменение registry или известный неуспех полной сверки запрещают использование записи готовности.

Перед Launch сверяются ревизия API и запись готовности, проверяется совместимость установленной игры; обход файлов исключён. При обновлении повторно проверяются только пути транзакции, а каждый установленный файл проверяется по SHA. Прежние неизменные файлы доверяются результату проверки. Самовольная правка модов или ошибка диска при прежней ревизии требует Full verification; это выбранный владельцем компромисс скорости и строгой проверки каждого запуска.

Host monitor связывает Docker container ID, StartedAt, фактический PID PZ, готовность игры и подготовленный набор модов. Сервер публикует ревизию только после сверки baseline и всех SHA-256. Изменение файлов активного набора блокирует раздачу.

Manifest содержит версию PZ, выбранные каталоги, пути, размеры и SHA-256. Клиент ограничивает декодированный JSON 64 MiB; метаданные поддерживают gzip. Файлы привязаны к ревизии; индивидуальная загрузка поддерживает Range.

Пакетная загрузка использует POST с максимум 4096 путями и поток tar.gz. Архив на сервере не сохраняется. Клиент принимает только запрошенные обычные файлы с ожидаемыми размерами, записывает их в собственный кеш и проверяет SHA. Неизвестные пути, ссылки и выход из каталога запрещены. При обрыве используется Range для той же ревизии.

Клиент проверяет локальные файлы перед обновлением и перед commit. Операции защищены lock, журналом транзакции, backups и registry владения. Полная таблица операций записывается один раз; небольшой журнал прогресса атомарно резервирует следующий пакет из 64 операций до изменения файлов. При восстановлении staged-файл и backup позволяют отличить выполненные операции от ещё не начатых; чужие файлы сохраняются. Registry служит точкой commit. Старые журналы поддерживаются при восстановлении.

Проверки symlink/junction и коллизий Windows сохраняются. Запуск игры блокирует изменение активного профиля; проверка процесса повторяется во время установки. Обнаружение неожиданного запуска сохраняет журнал для последующего восстановления.

SHA обеспечивает целостность. Доступ к API определяется Tailscale и его ACL; публичной публикации модпака нет.

Перезапуск сервера меняет ревизию даже при одинаковых файлах. Клиент вычисляет отпечатки каталогов из путей, размеров и SHA manifest и прежнего registry. Полная сверка требуется только для изменившихся каталогов; прочие файлы используют кеш проверенных SHA, привязанный к fingerprint (устройство, inode, размер, mtime и дополнительная временная метка). Отсутствующий кеш или изменение fingerprint требует повторного хеширования. Старый registry совместим; при первом переходе создаётся кеш метаданных.

Обычная проверка прежней ревизии повторно использует сохранённый manifest после проверки готовности и ревизии API. Полная проверка игнорирует кеш SHA. Мягкий режим не гарантирует обнаружение подмены, сохранившей все поля fingerprint; для этого предусмотрена Full verification. Кеш служит ускорению проверки, registry остаётся точкой commit и источником принадлежности файлов.

Переход на новый запуск с одинаковыми файлами обновляет только атомарный registry без переустановки. Pause обрабатывается во всех файловых циклах и между блоками хеширования/копирования по 1 MiB. Проверки скачанных файлов обязательны. Восстановление после отмены выполняется независимо от Pause, чтобы вернуть целостное состояние.
